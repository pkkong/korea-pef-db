# LP 2020년 이후 과거 공고 구축 계획

갱신: 2026-11-17 (작성: Codex)

최소 2020-01-01부터 현재까지의 국내 PE 출자 공고·후속 결과를 모아 기관별 연도 변화, 규모, 선정 GP, 전략 변화를 보여준다(2026-11-14 사용자 결정). 일일 수집 연결과 역사 자료 완성을 구분한다. 현재 실행과 기관별 공개 수는 [수집 현황](lp_collection_status.md), 마지막 검증 단계와 다음 작업은 [체크포인트](lp_resume_checkpoint.md)를 따른다. 이전 계획과 11월 7~15일 경과는 [history 원문](history/notes/lp_history_backfill_until_2026-11-15.md)에 보존했다.

## 현재 확보와 남은 범위

- 11/15 승인 발행으로 과거 31사업·33공고를 더했다. 11/16 09:14 공개 확인은 21기관 72사업이다. 이는 시장 전체 확보율이나 2020년 이후 전수 완료를 뜻하지 않는다.
- 24기관 중 18곳은 목록이 2020년 이전까지 이어진다. 16기관의 과거 원문 수집과 국민연금 옛 첨부 판독은 진행했으며, 결과·금액·마감·사업 연결의 기관별 공백이 남아 있다.
- 성장금융 2020~2022 저장 묶음은 162건(별도 `lp-history-bundles-kgrowth` 브랜치)이다. 검토용 묶음의 텍스트·해시만으로 raw 재생 검증을 완료했다고 하지 않는다. 원문 검증 경로가 없는 후보는 공개하지 않는다.
- 11/16 원래 실행 `43673216359`의 첨부85개를 찾았고 모두 파일 지문이 맞았다. 원래162건의 상세 HTML 공백 중 III 모집/결과2건을 자동 선택해 읽기 전용 `43868708985`에서 보완했다. 새 상세는 옛 바이트 지문과 다르지만 보관 필드 전체가 같으며 기존 PDF9,164자와 통합 재생도 보류0이다. 새 응답으로 옛 지문을 덮어쓰지 않는다. `lp_kgrowth_history_replay.py`와 저장 capture로 재현하며 같은 원문을 다시 받지 않는다. III의 국내 문구는 GP·LP 자격이므로 투자지역 근거를 따로 확보하기 전 공개하지 않는다.
- 같은 날 확보85개 전체 판독문도 원본에서 재생 일치했다. 혼합 법형태의 세컨더리4차·사업재편 양식은 공통 조건을 읽은 보류로 분리했고 PE 표·명단에 넣지 않았다. 다음은 비인용 성장지원 제목과 한 공고의 여러 펀드를 본문 구조로 나누는 판독이다. 중기중앙회2020/2021 두 공고는 검토용 가져오기·미리보기를 준비했지만 운영 state 합산 검증·승인 전이며 공개 수에 더하지 않는다.
- 11/17 성장지원의 성장금융 주관 리그와 복수 공고의 4펀드를 결과에 연결했다. 전체 정책출자 계획·주관 리그 합계·기관 단독 출자·결성목표는 구분한다. 숫자 회차의 표기 차이를 합쳐 64묶음·PE 표 2개·혼합 보류 표 7개가 됐고 나머지 미분류 50건은 보충 안내다. 새 PE 공개는 없으며 다음은 남은 현재 투자대상·독립 PE 트랙이 명시된 양식 우선 판정이다.
- 같은 날 남은 모집 40묶음의 현재 법형태·투자대상을 분류했다(성장금융 귀속의 추가 독립 PE 0/혼합 36/VC 법형태 1/미확정 3). 공동 원문의 산업은행 주관 소부장2021·정책형뉴딜2021은 2024년 이전 은행 이력의 별도 검토 후보로 남겼다. 게시 사이트나 병합 표의 값 순서로 기관을 재귀속하지 않으며, 원본·현 범위·후속 단계·중복 확인과 승인 전에는 운영에 넣지 않는다.
- 산업은행은 2024-01, 기업은행은 2024-12 이전 자료가 현재 게시판에 없었다. 협회·공동 공고·주간운용사 원문을 먼저 찾고, 원문이 없을 때만 출처를 붙인 보도 기준 결과를 검토한다.

## 작업 순서

1. **OCIO 결과 연결:** 산재보험기금 삼성자산운용 결과의 정기 발행·공개 명단과 기존 주소를 확인한다. 고용보험기금 미래에셋증권(2023.7~)은 실행기 읽기 검증 뒤 정기 수집에 켜고, 한국투자증권(2015.7~2023.6)의 과거 PE 결과를 보완한다. 미발견을 결과 없음으로 단정하지 않는다.
2. **성장금융 전용 과거 판독:** 펀드명·회차·연도로 모집과 결과를 묶고 PE/PDF/VC, 블라인드/프로젝트, 일반/루키를 분리한다. PEF 법형태만으로 블라인드 범위를 확정하지 않는다. Co-GP의 펀드 수와 GP 수를 구분하고, 계획 수와 결과 수가 다른 명단은 무리하게 연결하지 않는다. 정확한 첫 묶음부터 원문 재생과 기존 주소·조건 보존을 검증한다.
3. **나머지 형식과 원문 공백:** 캠코 2022 자본확충형, 중기중앙회 옛 PE·VC, 건설근로자 재수집, 사학연금 2020~2021 이미지 OCR, 산재 마감, 수은·우본 과거, 은행 2024년 이전을 기관별 작은 묶음으로 처리한다. 이름·공고 ID 예외 목록으로 채우지 않는다.
4. **기관별 연도 비교:** 검증된 모집 사업 단위로 PE 계획 출자액, 리그·주목적·요건 변화, 공식 선정 GP를 비교한다. 사업 총액·PE/VC 합계·실제 GP별 약정/납입을 분리한다. 공백은 0으로 채우지 않는다.

## 수집·판독·공개 기준

- 출처는 기관 자체 → OCIO·주간운용사 → 협회 재게시 → 보도 기준 순이다. OCIO 공고는 기금명을 명시할 때 위탁 기금으로 연결한다. 공식 결과가 생기면 같은 사업의 보도 기준 결과는 숨긴다.
- 기존 저장 목록·본문·첨부와 해시를 먼저 재사용한다. 부족한 원문만 기간·페이지·파일 크기·재시도 상한 안에서 수집하며, 공식 HTTP는 기존 `lp-program-collection` 공유 큐를 쓴다. 실패 응답은 파싱 전에 제한 진단으로 보존한다.
- 모집→정정/취소→접수/서류→우선협상→최종선정을 같은 사업의 단계로 연결한다. 연도·회차·펀드·투자 범위가 다르면 분리한다. 모집 계획과 접수 명단을 최종 선정으로 올리지 않는다.
- 공개된 사업 주소·검토 결정·확인된 모집조건·선정 명단을 보존한다. 같은 공고 병합은 별칭 쪽으로 이전 주소를 남긴다. 모든 단계는 원문 이름·공고 URL과 함께 재현 가능해야 한다.
- 원문 문서 수·보관 버전 수·PE 사업 수·선정 펀드 수·운용사 수는 따로 센다. 확보한 목록 몇 쪽으로 시장 누락률이나 전수 완료를 계산하지 않는다.

## 검증과 실행 경계

- 로컬 기준은 Python 3.12와 공통 의존성이다. `python3 scripts/run_regression_tests.py`, `python3 scripts/check_architecture_contracts.py` 및 해당 원문 재생 검사를 통과한다.
- 새 게시판 채널은 운영 비활성으로 구현한 뒤 `data/lp_board_channel_check_request.json` push의 읽기 전용 실행기 검증을 먼저 한다. 성공 여부뿐 아니라 발견 공고·보류·PE 명단을 본다.
- 운영 DB 쓰기·수동 수집/발행·배포는 사용자 승인 경계를 따른다. 이미 승인된 GitHub Actions 정기 수집과 읽기 전용 확인은 유지한다. 시간 초과 뒤에는 DB 상태 읽기 확인 전 재시도하지 않는다.
- 반복 예약은 새로 켜지 않는다. 교대 규칙에 따라 사용자 확인이 있어야 한다. 채팅·예약 메모 대신 저장소 문서와 `Agent: Codex`/`Agent: Claude` trailer가 있는 commit으로 이어받는다.
- 한 단위가 끝나면 체크포인트에 작성 에이전트, 로컬 검사, 운영 반영 여부, 다음 작은 단위를 남긴다. 시작 문서 네 개는 각 40KB 이하로 유지한다.
