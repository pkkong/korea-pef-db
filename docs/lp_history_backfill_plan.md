# LP 과거 공고 구축 계획

기준 확정: 2026-11-06 사용자 지시. 최소 대상 기간은 **2023-01-01부터 현재까지**다. 2026년 현재 네 개 연도이며, 앞으로도 시작일을 매년 밀지 않는다. 기존24기관과 국내 PE 블라인드 판정 기준을 유지한다.

## 목적과 완료 기준

- 기관별 출자사업·모집 규모·선정 횟수와 이후 LP–GP 선정 이력 비교의 기초 자료를 만든다. 수집기 연결 완료와 과거 DB 구축 완료를 구분한다.
- 기간 안에 게시된 모집·정정·취소·접수·심사·최종 선정 자료를 발견하고 같은 사업/차수/PE 트랙에 묶는다. 연결에 필요한 기간 밖 원공고는 근거로 확보하되 모든 과거로 범위를 넓히지 않는다.
- 기관×연도마다 공식 목록의 기간 경계, 발견 후보, 확보 본문/첨부, 범위 판정, 사업/단계 연결, 남은 오류·접근 제한을 기록한다. 자료0건과 미탐색을 구분한다. 모집 공고와 결과를 각각 사업1건으로 합산하지 않는다.
- 공식 선정 명단은 LP 데이터와 상세 화면의 필수 정보다. GP 프로필/별칭 통합은 후순위여도 선정 결과 원문과 이름 확보·표시는 미루지 않는다. 결과 발표 원문 확보, 명단 판독, GP 식별 연결을 별도로 기록한다.
- 선정·우선협상·약정·납입은 다르다. 선정 발표를 실제 수령/납입으로 표시하지 않는다. 공통 PE/VC 합계나 사업 총액을 GP별 출자액으로 나누어 추정하지 않는다.
- 공식 결과가 비공개/미게시이면 해당 한계를 남긴다. 접근 제한을 우회하거나 추정 이름을 넣지 않는다. 전체 시장 누락률이나100%를 원문 건수로 계산하지 않는다.

## 수행 순서

1. **기존 보관 자료의 연도별 현황 산출.** 입력 보고서와 Supabase의 보관 원문 전체를 구분한다. 먼저 저장 artifact를0HTTP로 집계하고, 다음에는 Actions의 읽기 전용 DB 목록으로 기관·연도·원문URL·버전·일자 충돌·선정 단계 확보 여부를 대조한다. 최신 수집 artifact만으로 전체 DB 확보량을 단정하지 않는다.
2. **2023년부터 공식 목록 발견.** 기관·검색·기간·페이지별 경계를 저장한다. 최근365일/연도/페이지/본문 상한을 단순히 크게 바꾸지 않는다. 고정 시작일과 이어받기 가능한 별도 과거 수집 경로에서 기존 파서를 재사용한다.
3. **부족한 원문·첨부만 제한된 묶음으로 수집.** 기존URL/내용 지문과 원문 검증 결과를 재사용한다. 목록→본문/첨부→PE 범위→사업/단계 연결 순서로 이어가며 재시도 상한·실패 이력을 유지한다. 공식 HTTP는 기존 `lp-program-collection` 공유 큐에서만 실행한다.
4. **종결 사업의 결과 보강.** 공식 후속 결과를 사업 정체성으로 자동 연결하고 선정 GP 이름과 원문을 저장한다. GP 이름이 이미 있는데 상세에서 빠지는 문제와 결과 미수집을 분리해 수정한다. 접수 마감만 지난 사업을 선정 완료로 바꾸지 않는다.
5. **운영 DB·공개 검증.** 기존 사업 주소·확인된 조건/선정 정보와 다른 서비스 독립성을 보존한다. 연도별 자료와 상세 화면을 검증한 뒤 통계 입력으로 사용한다. 진행 중인 정기6회/주간 감사 검증도 유지한다.

## 실행과 재개

- 일일 최신 수집과 과거 복원은 작업 경로를 나누되 같은 공식 출처 큐를 사용한다. 최근 공고 갱신을 과거 수집 때문에 중단하지 않는다.
- 현재 채팅의 `lp-db` 예약을1시간 간격으로 유지한다. 실제 미완료 묶음·검사·필요한 반영을 수행하고 완료 지점/다음 항목을 체크포인트에 기록한다. 사용량 제한은 완료가 아니며 다음 예약에서 재시도한다. 이미 실행 중인 작업은 중복 시작하지 않는다.
- `docs/lp_resume_checkpoint.md`와 `docs/lp_collection_status.md`에 실제 결과를 남긴다. 예전 문서의 ‘모든 과거를 추가하지 않음’은 이번 사용자 지정2023년 시작 범위를 금지하는 규칙으로 해석하지 않는다. 로그인·GP 서비스 개발·기관 추가는 여전히 별도다.
