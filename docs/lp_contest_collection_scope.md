# LP 출자공고 수집 범위와 출시 기준

## 2026-10-13 범위 확장

사용자는 4기관만으로 출시하는 안을 거절했고, 국내 PEF 블라인드 공식 공개모집 기관을 빠르게 넓혀 확인하도록 지시했다. 기존 4기관은 수집 연결이 먼저 된 기관이지 출시 범위의 상한이 아니다. GP 프로필 연결, 로그인, AUM 전수 조사와 모든 연도 복원은 첫 출시에서 미룬다.

## 자동 수집 경로

기존 기관별 공식 수집기에 한국벤처캐피탈협회와 금융투자협회 2개 게시판을 추가한다. 공식 기관 명의로 게시된 공고 본문과 첨부를 읽으며 협회를 별도 LP로 등록하지 않는다. 기관·채널 설정은 관리하지만 신규 공고 ID를 골라 넣는 허용목록은 만들지 않는다. 목록 링크를 따라 새 공고를 발견하고 기관 연결과 PE/VC/블라인드 범위를 코드로 판단한다.

`collect_shared_lp_notices.py`는 3개 게시판 각 3페이지를 읽는다. `lp_shared_notice_catalog.py`와 발행기는 주소·기관·날짜·첨부 근거를 다시 검사해 Supabase에 보존하고 기존 검토 화면에 연결한다. 원문을 읽었다는 이유만으로 금액·선정 GP·새 공개 사업을 만들지 않는다. 게시판에서 사라지거나 일시 장애가 생겨도 기존 자료는 보존한다.

KVCA 원공고일이 접수 마감보다 뒤로 적힌 사례는 협회 등록일을 별도로 표시하고 원공고일을 미확정으로 둔다. 과거 블라인드펀드 운용 경력은 현재 모집 유형의 근거에서 제외한다. 제출 양식은 모집 조건의 근거로 사용하지 않는다.

운영 workflow는 평일 09:20·15:20 기존 예약에 공통 수집을 함께 실행한다. 목록·상세 수집 장애는 실행 실패로 알리고, 지원하지 않는 첨부 구조는 검토 대상으로 남긴다. 첨부 판독 성공과 모집 조건 추출 성공을 구분한다.

## 원공고 연결과 모집정보 정리 (2026-10-14)

`collect_lp_original_notices.py`는 협회 공고 안에서 발견된 링크만 따라가며 해당 기관의 공식 도메인·제목·연도·차수·모집 단계를 대조한다. 일반 공고와 재공고·변경 공고를 섞지 않는다. 기관명을 페이지 하단에서 발견했다는 이유만으로 원공고로 인정하지 않는다. 원공고 본문·게시일·첨부·파일 지문을 별도로 보존하고 발행기에서 다시 검사한다. 기관 도메인은 설정하지만 개별 공고 ID는 지정하지 않는다.

실제 표본에서 원공고 추적 대상 15건 중 링크가 있는 1건(군인공제회)을 확인했다. 기관 원문 게시일은 2026-07-31이며 협회 등록일 8월 5일과 구분한다. 링크가 없는 14건은 기관 원공고 연결 완료로 처리하지 않는다. 군인공제회 본문은 읽었지만 동적 첨부목록은 아직 지원하지 않는다.

`lp_shared_notice_terms.py`는 같은 공통 규칙으로 금액·선정 수·펀드별 출자액·주목적·접수 마감·심사 예정 일정을 정리한다. 전체 합계/PE/VC 열과 표 단위, 금액 합계와 선정 수를 검산한다. PE 배분이 없는 통합 모집은 PE·VC 합계로 표시하며 선정 수나 펀드별 금액을 임의로 나누지 않는다. 월·주차·월말~다음 월초 표현은 날짜를 만들어 넣지 않고 원문 정밀도로 보존한다. 날짜가 지난 예정 심사를 완료된 결과로 바꾸지 않는다. 별도 주목적이 없으면 관련 필드를 생략한다.

## 기관 공식 게시판 원공고 탐색 확장 (2026-10-14)

`discover_lp_original_boards.py`와 `data/lp_original_board_channels.json`은 과학기술인공제회·중소기업중앙회·자산관리공사·공무원연금의 실제 목록/검색/페이지 이동을 읽는다.
