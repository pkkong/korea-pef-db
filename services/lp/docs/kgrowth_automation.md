# 한국성장금융 수집 운영

## 범위

한국성장금융 공식 출자사업 게시판 최신 목록 1페이지와 검토된 밸류업펀드3차 공고 1047·1075·1090·1100을 추적한다. 과거 전체 공고 백필이 아니다. 한 번 발견한 공고는 `tracked_notices`에 저장해 최신 목록 밖으로 밀려나도 계속 확인한다. 수집 시작 전에 목록에서 이미 빠진 과거 공고는 별도 백필이 필요하다.

수집 workflow `Collect Korea Growth LP programs`는 평일 09:20·15:20 KST 실행. GitHub schedule 지연 가능. 수동 workflow_dispatch 가능.

현재 자동 반영 범위는 검토된 밸류업3차의 공식본문 재검증, 접수17팀·숏리스트6팀·최종3사 명단 대조와 페이지 발행이다. 신규사업 자동분류/신규GP명부 생성/첨부 투자조건 자유추출은 구현되지 않았다. 신규 12건 같은 미검토 공고는 검토대기로 보관하며 자동 공개하지 않는다.

## 데이터와 발행

- `lp_program_private.collection_runs`: 실행별 수집/검토보고서.
- `documents`: URL과 문서지문별 원문 근거.
- `program_state`: 기존 5사업 데이터와 승인된 원문지문, 렌더링된 페이지. 한 트랜잭션으로 교체.
- 공개는 `public.lp_program_page` RPC를 통한 HTML만. 원문/검토대기 데이터 접근권한은 공개하지 않는다.
- Vercel `/samples/lp/`는 Supabase를 읽는다. DB 읽기실패는503, 없는페이지404. 옛배포사본으로 조용히되돌리지 않는다.
- 수집실패·빈결과·명단불일치는 발행중단. 본문/첨부변경은 requires_review로 기존사업보존. 승인된 fingerprint를 DBbaseline으로 재사용해 다음실행에서 변경이 자동승인되지 않게 한다.

## 검수와 한계

수집보고서는 GitHub Actions artifact `kgrowth-collection` 및 DB collection_runs에서 확인. 변경원문 검수 후 명시적으로 승인된지문/사업자료를 갱신하는 관리UI는 아직 없다. 정정공고의 기존사업 영향은 수동검토 대상이다. 다른4기관 일정상태는 샘플시점이므로 자동최신으로 설명하지 않는다.

## 검토 화면 (2026-09-29)

Vercel `/admin/lp`는 로그인 화면만 공개한다. 검토 데이터와 승인 RPC는 Supabase Auth의 확인된 이메일 + `lp_program_private.reviewers` 등록을 모두 요구한다. 서비스 역할 키와 DB URL은 브라우저/앱에 추가하지 않는다. 확인된 사용자 이메일을 명시적으로 받은 후 `Configure LP reviewer` workflow로 등록한다. 계정은 사용자가 화면에서 생성하고 확인 메일을 통해 이메일 소유를 확인한다. Supabase 이메일 발송·가입 설정이 실제 계정에서 지원되는지 별도 확인이 필요하다.

화면에서 공고 원문/첨부, 기존 사업/새 사업 연결, 단계별 공고 선택, 공개 중 정보와 수정안을 비교하고 승인·보류·제외할 수 있다. 승인 시 현재 수집 실행과 원문들을 DB가 직접 저장하며, 수집이 바뀐 화면에서는 승인을 거절한다. 승인 기록은 삭제하지 않는다. 다음 예약/수동 수집이 원문·첨부 지문을 재확인한 뒤 공개한다. 승인 즉시 공개되는 구조는 아니다. 보류/제외는 검토 분류이며 기존 공개 사업을 삭제하지 않는다. 제외한 공고도 원문이 변경되면 재검토 상태로 돌아온다.

수동 승인한 사업은 자동 recipe가 덮어쓰지 않는다. 같은 사업의 더 최신 승인본이 있으면 이전 승인본으로 되돌리지 않는다. 승인 이후 근거 변경 시 이전 발행본을 유지한다. 접수/서류/최종 GP 입력은 공동운용팀을 한 줄로 유지한다. 기존 분야별 출자표가 있는 사업의 총액 변경은 화면에서 차단한다(분야별 조건 편집은 추가 지원 필요). 신규 PDF의 조건 추출을 자동으로 승인하는 기능이 아니다.

## 로그인 보류 — 현재 운영 방식

사용자 지시에 따라 로그인/가입/계정등록은 보류한다. `/admin/lp`는 로그인 없는 읽기 전용 공고 검토 화면이다. 수집 발행 시 공식 공개 공고의 제목·날짜·본문·원문 링크와 공개 사업 요약만 `review.html`로 생성한다. 계정, 승인기록, 내부 보고서 전체는 공개하지 않는다. 같은 주소의 로그인 UI/JS는 제거했다. 수정·승인·반영 요청은 대화로 받고 에이전트가 처리한다. 이메일 등록 요청은 취소되었으며 현재 필수 단계가 아니다. 기존 쓰기 RPC의 권한 제한은 유지하고 공개 쓰기 권한을 추가하지 않는다.
