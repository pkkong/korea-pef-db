# 한국성장금융 수집 운영

## 범위

한국성장금융 공식 출자사업 게시판 최신 목록 1페이지와 검토된 밸류업펀드3차 공고 1047·1075·1090·1100을 추적한다. 과거 전체 공고 백필이 아니다. 한 번 발견한 공고는 `tracked_notices`에 저장해 최신 목록 밖으로 밀려나도 계속 확인한다. 수집 시작 전에 목록에서 이미 빠진 과거 공고는 별도 백필이 필요하다.

수집 workflow `Collect Korea Growth LP programs`는 평일 09:20·15:20 KST 실행. GitHub schedule 지연 가능. 수동 workflow_dispatch 가능.

현재 자동 반영 범위는 검토된 밸류업3차의 공식본문 재검증, 접수17팀·숏리스트6팀·최종3사 명단 대조와 페이지 발행이다. 신규사업 자동분류/신규GP명부 생성/첨부 투자조건 자유추출은 구현되지 않았다. 신규 12건 같은 미검토 공고는 검토대기로 보관하며 자동 공개하지 않는다.

## 데이터와 발행

- `lp_program_private.collection_runs`: 실행별 수집/검토보고서.
- `documents`: URL과 문서지문별 원문 근거.
- `program_state`: 기존 5사업 데이터와 승인된 원문지문, 렌더링된 페이지. 한 트랜잭션으로 교체.
- 공개는 `public.lp_program_page` RPC를 통한 HTML만. 원문/검토대기 데이터 접근권한은 공개하지 않는다.
- Vercel `/samples/lp/`는 Supabase를 읽는다. DB 읽기실패는503, 없는페이지404. 옛배포사본으로 조용히되돌리지 않는다.
- 수집실패·빈결과·명단불일치는 발행중단. 본문/첨부변경은 requires_review로 기존사업보존. 승인된 fingerprint를 DBbaseline으로 재사용해 다음실행에서 변경이 자동승인되지 않게 한다.

## 검수와 한계

수집보고서는 GitHub Actions artifact `kgrowth-collection` 및 DB collection_runs에서 확인. 변경원문 검수 후 명시적으로 승인된지문/사업자료를 갱신하는 관리UI는 아직 없다. 정정공고의 기존사업 영향은 수동검토 대상이다. 다른4기관 일정상태는 샘플시점이므로 자동최신으로 설명하지 않는다.

## 지속 추적 보완 (2026-09-28)

검토 대기와 추적 명단은 별개다. 새 공고도 이후 실행에서 계속 조회하지만 공개 승인으로 취급하지 않는다. 동일 원문은 확인 시각만 바뀌어도 중복 버전을 만들지 않는다. 수집 workflow는 DB 발행 후 Vercel 응답의 실행 식별자와 본문을 확인하며, 불일치하면 실패 처리한다. 신규 공고 첨부의 내용 추출과 변경 비교, 과거 전체 목록 백필, 검수 승인 화면은 아직 지원하지 않는다.

## 두 번째 사업: K-컬처 밸류업 (2026-09-29)

`data/kgrowth_program_reviews.json`은 검토한 사업 연결, 공고·첨부 지문, 항목별 원문 인용과 페이지, 분야명 대응을 보관한다. 새 사업 전체 HTML이나 GP 명단을 직접 쓰지 않는다. `kgrowth_program_review.py`가 공고 본문에서 분야별 명단을 추출하고 공통 상세 자료로 변환한다. 규모·주목적·마감은 최초 검토한 값과 PDF 인용을 대조하여 재사용한다. 임의의 새 PDF에서 투자 조건을 자유롭게 자동 추출하는 기능으로 설명하지 않는다.

- K-컬처 원문: 모집1089, 접수1106, 서류심사1114, 최종1120. 첨부 PDF는 수집 때 다운로드하여 SHA와 pypdf 6.10.0 추출문을 대조한다.
- 정책출자 총800억원(모펀드500+산업은행170+첨단기금130), AI·IP500/콘텐츠혁신300억원·각1개사. 한국성장금융 단독 출자금으로 해석하지 않는다.
- 접수 마감8월12일16시와 접수 결과 게시8월13일을 구분한다. 접수13팀→서류6팀→최종2개사. 목적비율의 분모는 목표 결성액이다.
- 심사/최종 명단은 분야별로 검증하고, 공동운용팀을 임의로 분리하지 않는다. 표기 차이는 검토한 대응만 사용한다. GP master 자동 병합은 하지 않는다.
- 새 관련 공고, 첨부 변경, 근거 인용 불일치는 해당 사업 발행을 보류하고 기존 공개 정보를 유지한다. 다른 승인 사업은 계속 갱신할 수 있다.
- 검토 대기는 `candidate_groups`로 묶어 DB 및 Actions JSON/Markdown artifact에 저장한다. 연락처/기타 안내, 재공고, 제출서식을 구분하며 같은 이름의 차수를 자동 합치지 않는다.
- 신규 승인 절차: 원문과 첨부 확인 → registry에 근거/지문/분야/값 추가 → 테스트·수집 미리보기 검증 → 커밋 및 수집 workflow. 별도 관리자 승인 UI는 아직 없다.
